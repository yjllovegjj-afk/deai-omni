# 去AI味 · 全域增强版（deai-omni）

一个中文写作的去机械化规则库，WorkBuddy 技能。日常写作里说「去AI味 / 说人话 / 自然点」时默认用它。

规则来自全网检索并交叉验证：OpenAI 和 Anthropic 的官方文件、维基百科现行版、283 万字语料研究、光明日报、番茄/起点/小红书的官方规则，每条都标了来源。

---

## 1. 项目解决什么问题

写作时最容易踩的三个坑，这个项目专门治：

- **一眼假**：满篇「值得注意的是」「综上所述」「赋能闭环」，读着像机器写的。市面上的去AI味清单多半是给你一张词表让你换词，换完还是那副骨架。
- **越改越假**：很多流传很广的规则其实已经过时或根本是错的。比如 `delve` 早被维基移进历史指标，破折号是弱指标而且因模型而异，设问句人类用得比 AI 多 17 倍。一刀切地删，反而把人味改没了。
- **不知道该改到什么程度**：自媒体说要「彻底去AI化」，平台又说 AI 占比超 10% 就撤榜。到底改多少、哪些场景红线不能碰，没有准数。

这个技能的做法是：按**当下还有效的特征 + 写作场景 + 来源模型指纹**来改，先动结构、再动句式、最后才换词；同时单列一张「禁止改白名单」，专门撤销误杀。它**只提示不评分**，不输出 AI 疑似度分数，也不承诺「改完能过某个检测器」。

> 分工：本技能是日常默认的规则库；要「过朱雀 / 降AI率 / 过审 / 番茄起点」这类检测器对抗需求，用 `deai-promax`；纯英文快速扫一遍用 `humanizer`。

## 2. 主要功能

### 五步改写工作流（Skill 的核心）

| 步骤 | 做什么 |
|---|---|
| 0 判断场景与模型 | 先定场景（网文/公众号/小红书/短视频/通用），可选推断来源模型 |
| 1 自查 | 跑脚本或手动查：黑名单命中、标点密度、句长与设问句节奏 |
| 2 分层改写 | 结构层 → 句式层 → 词汇层，按顺序改，不一上来就换词 |
| 3 撤销误杀 | 对照白名单，把改错的设问句、比喻、破折号还原回来 |
| 4 交付 | 改写文本 + 改动清单表 + 误杀复查勾选，改动率控制在 10% 以内 |

核心原则：只改「怎么说」不改「说什么」，不新增事实、数字、因果；拿不准就不改。

### 自查脚本 `omni_scan.py`

零依赖，Python 3 直接跑，做四件事：

1. **12 类中文黑名单命中**：开场清嗓、总结腔、意义通胀、汇报腔、商业黑话、工程师腔、暴力动作腔、自媒体腔、网络梗、学术黑话、洞见骨架、冗余副词，输出词和行号。
2. **标点密度**：破折号、提示性冒号按千字归一化，按模型差异化看待。
3. **节奏参考**：句数、平均句长、句长 CV、问号数，用来防止误杀。
4. **来源模型提示**：按破折号密度和对举结构推断可能是哪个模型写的，可用 `--model` 指定。

设计红线：**不评分、不做通过判定、不对抗检测器**。命中多不等于必改，先抽样 20 条再看频率。

## 3. 安装方法

把它放进 WorkBuddy 的技能目录即可，系统会自动发现含 `SKILL.md` 的目录，不用手动导入。

**从 GitHub 克隆到技能目录：**

```bash
cd "$HOME/.workbuddy/skills"
git clone https://github.com/yjllovegjj-afk/deai-omni.git
```

**已有仓库时更新：**

```bash
cd "$HOME/.workbuddy/skills/deai-omni"
git pull
```

脚本要 Python 3（只用了标准库，不用装依赖）。克隆后想单独验证脚本：

```bash
python scripts/omni_scan.py            # 不带参数会打印用法
```

> `$HOME` 指当前用户的家目录：Windows 通常是 `C:\Users\<用户名>`，macOS/Linux 通常是 `/home/<用户名>` 或 `/Users/<用户名>`。按你的实际环境替换。

## 4. 使用方法

### 方式一：在 WorkBuddy 里直接说（推荐）

说出触发词即可，技能会被自动调用：

- 「这段文案读起来像 AI，帮我去掉AI味」
- 「说人话一点」
- 「按小红书的调性改得自然点」

它会先判断场景和来源模型，跑自查，按结构→句式→词汇改，撤销误杀，最后给你**改写文本 + 改动清单表 + 误杀复查勾选**。

如果检测到「过检测 / 降AI率 / 过审」的意图，它会主动提示改用 `deai-promax`，不硬接。

### 方式二：命令行自查

```bash
python scripts/omni_scan.py <你的文稿路径>
python scripts/omni_scan.py <你的文稿路径> --model gpt     # 已知来源模型时指定
python scripts/omni_scan.py <你的文稿路径> --model auto    # 默认，自动推断
```

可选模型：`claude | gpt | deepseek | kimi | gemini | auto`。脚本只读文件、只输出提示，不会修改你的文稿。

### 自已手动查（没有 Python 时）

按 SKILL.md 第 1 步：grep 黑名单词、数破折号、看句长是否高度一致、数设问句，然后对照 `02` 和 `05` 两份文件处理。

## 5. 输入示例

### 示例 A：在 WorkBuddy 里这么用

```
用户：这段小红书文案读起来像 AI，帮我改一下。
      很好用，性价比很高，值得入手，建议收藏。

技能：判断场景=小红书 → 读 03 小红书栏（红线：AI 占比 25–30%）
      → 跑脚本命中「很好用」「性价比很高」等
      → 按 02 处理：「很好用」改成有体感的描述
      → 对照 05 撤销误杀 → 交付改写文本 + 改动清单 + 误杀勾选
```

### 示例 B：命令行自查（真实运行输出）

准备一个 `demo.txt`：

```text
值得注意的是，在这个快节奏的时代，赋能行业闭环是至关重要的。
真正的护城河恰恰是底层逻辑——这不是简单的打磨，而是深度的沉淀。
综上所述，它标志着一个里程碑式的突破，意义非凡。
你以为是效率问题？其实是心智问题。
```

运行：

```bash
python scripts/omni_scan.py demo.txt
```

实际输出（节选）：

```text

============================================================
文件：demo.txt
汉字数：91

[1] 中文黑名单命中
    1-开场清嗓（1 处）
      值得注意的是  L1
    11-洞见骨架（4 处）
      真正的  L2   恰恰是  L2   你以为是  L4   其实是  L4
    2-总结腔（1 处）
      综上所述  L3
    3-意义通胀（4 处）

    合计 16 处命中。注意：命中 ≠ 必须改，先看频率再抽样 20 条。

[2] 标点密度（按模型差异化，别一刀切）
    破折号——: 1
    破折号密度/千字: 10.99

[3] 节奏参考（防止误杀）
    句数: 5
    平均句长(汉字): 18.2
    句长CV: 0.5
    问号数(设问句参考): 1
    提醒：设问句人类使用频率是 AI 的 17 倍，不要因为'像 AI'就删。
```

看懂这份报告是关键：它**列出疑似点但不打分**。16 处命中里，「你以为是…其实是…」属于洞见骨架，改的时候要留意别把设问句一并删掉；破折号密度高只说明可能是 DeepSeek 写的，不是「必须删」。具体改法和撤销误杀的规则见 `02` 和 `05`。

## 已知边界

- 文心一言等国产模型没有量子数据，标 `TBD-需实测`，用通用规则处理。
- 不承诺「改完能通过某检测」，也不输出 AI 率分数；要过检测器请用 `deai-promax`。
- 规则数据截到 2026-11，平台规则大变动时需更新对应 reference。
- 英文文本能处理，但纯英文快速扫用 `humanizer` 更快。

规则均来自公开资料，来源见 `references/06-source-index.md`。
